# 06 精度一致性验证

## 1. 阶段目标

使用统一数据集和统一后处理协议,对 PyTorch、ONNX 和 MTK NPU INT8 逐级比较,确定精度从哪一级开始变化.

## 2. 评测层级

```text
PyTorch FP32
  → FP32 ONNX
  → MTK INT8 TFLite/NPU 原始输出
  → 板端 C++ 完整前后处理结果
```

需要同时关注：

- tensor 数值一致性.
- 检测框和类别一致性.
- 完整 COCO mAP.
- 相邻阶段精度损失.

## 3. 正式执行入口

容器内运行 `bash models/perception/object_detection/yolov5s/deploy/run.sh`,生成同协议 ONNX 参考并上传模型和程序.在板端部署目录运行 `bash run.sh`,执行全量推理、COCO 评价和汇总.

`-test` 仅用于固定小子集流程检查,不代替正式 COCO 结果.每次运行使用独立编号;需要恢复中断任务时确认模型、配置和输入均未变化.

## 4. 统一协议

- 数据集：COCO val2017,5000 张.
- 输入：letterbox `640×640`.
- confidence：`0.001`.
- NMS IoU：`0.6`.
- max detections：`300`.
- 三后端共享相同解码和 NMS 语义.
- 清单内所有图片都纳入评测,即使某张没有检测结果.

本项目 NMS IoU 为 0.6,而上游官方复现常用 0.65,因此本项目三后端之间的损失对比有效,但不应声称与上游官方协议完全相同.

## 5. 结果核对

检查参考与板端使用相同图片、标注、阈值和评分实现,再计算绝对指标与差值.具体成绩统一保存在模型的 `results/summary.json`,不在学习文档重复维护.

## 6. 精度下降排查顺序

1. 确认评测图片、标注和 image ID 完整一致.
2. 确认 PyTorch 与 ONNX 的输入和输出一致.
3. 比较 INT8 前后的代表性 tensor.
4. 检查 RGB/BGR、letterbox padding、归一化、scale 和 zero point.
5. 检查 MDLA 输出布局和 stride.
6. 检查 anchor、sigmoid、坐标变换、NMS 阈值和坐标回映.
7. 只有确定损失来自量化后,才考虑增加校准代表性、敏感度分析或混合精度.

## 7. 通过标准

- 5000/5000 图片完成并与标注 image ID 对齐.
- 各后端使用同一评测协议.
- 相邻阶段差异有量化结果和解释.
- 没有用校准集、COCO128 或三张展示图片代替正式 COCO val2017.
- 指标、日志和运行清单绑定到同一运行 ID.
