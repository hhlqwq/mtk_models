# 07 性能分析与优化

## 1. 阶段目标

在精度满足要求的前提下，区分预处理、NPU、后处理和端到端耗时，记录分位数、峰值内存和运行条件，并用证据定位瓶颈。

## 2. 性能口径

| 指标 | 包含内容 |
| --- | --- |
| 纯 NPU | Runtime 单次模型执行 |
| 预处理 | JPEG 读取、letterbox、颜色转换和 INT8 量化 |
| 后处理 | 输出还原、dequantize、YOLO 解码、NMS 和坐标回映 |
| 端到端 | 预处理 + NPU + 后处理 |

稳态端到端统计不包含一次性模型加载、最终 JSON 序列化和 COCOeval。

## 3. 正式采集方法

- 模型只加载一次。
- 先执行固定次数预热。
- 对完整数据集逐图记录耗时。
- 同时计算平均值、P50、P90 和 P95。
- 记录进程峰值 RSS。
- 记录板端系统、内核、Runtime、CPU governor 和频率范围。
- 保存逐图 CSV 和汇总 JSON。

## 4. 已完成结果

| 项目 | 平均或结果 | P95 |
| --- | ---: | ---: |
| C++ 预处理 | 7.716 ms | 11.039 ms |
| C++ NPU | 9.629 ms | 9.696 ms |
| C++ 后处理 | 16.173 ms | 17.662 ms |
| 稳态端到端 | 33.662 ms | 38.009 ms |
| 等效吞吐率 | 约 29.71 FPS | 不适用 |
| 峰值 RSS | 33,224 KiB | 不适用 |

当前主要时间不在纯 NPU，而在后处理，其次是预处理。优化时应先确认瓶颈占比，再决定是否投入。

## 5. 优化顺序

1. 固定模型、数据集、阈值和 CPU governor，建立可重复基线。
2. 检查 JPEG 解码、内存复制和颜色转换。
3. 检查输出解交织、解码循环和 NMS 复杂度。
4. 减少不必要的临时 buffer 和重复分配。
5. 评估线程化或流水线并发，但分别报告单路延迟和吞吐率。
6. 使用 Neuron Studio 检查 NPU 利用率、内存带宽和子图耗时。
7. 每项优化必须重新检查精度，不允许只看延迟。

## 6. 性能报告必须记录

- 模型和 DLA 哈希。
- 板端型号、系统、内核和 Runtime。
- 输入尺寸、batch 和数据类型。
- 预热次数和统计样本数。
- CPU governor、频率范围和并发设置。
- 平均值和分位数。
- 峰值内存。
- 优化前后收益、代价和精度变化。

## 7. 通过标准

- 指标来自目标板，不是 89 的 GPU。
- NPU 延迟与端到端延迟没有混写。
- 预热、样本数和分位数完整。
- 优化前后使用相同协议。
- 性能改善没有破坏精度或输出完整性。
