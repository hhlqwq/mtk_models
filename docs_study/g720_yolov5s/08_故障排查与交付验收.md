# 08 故障排查与交付验收

## 1. 阶段目标

按错误发生阶段定位问题,保留完整证据,并以可复现的交付清单结束流程.

## 2. 先判断失败发生在哪一层

| 阶段 | 常见现象 | 首要检查 |
| --- | --- | --- |
| 来源准备 | 哈希不匹配、权重无法加载 | URL、版本、文件完整性和许可证 |
| PyTorch/ONNX 导出 | 动态维度、算子导出失败 | 锁定源码、opset、输入 shape、MTK patch |
| Converter | 不认识源算子或量化失败 | Converter 版本、算子、校准输入和 dtype |
| NCC | 某算子无法映射到 MDLA | NP8 算子表、rank/shape/dtype、目标架构 |
| 板端加载 | unsupported target、缺少库、模型拒绝 | DLA arch、Runtime、驱动、固件和系统镜像 |
| 板端输出 | 输出全零、重复或框异常 | buffer 更新、量化参数、输出布局和 stride |
| 精度 | mAP 明显下降 | 数据清单、预处理、解码、NMS、量化敏感节点 |
| 性能 | NPU 或端到端异常慢 | governor、CPU fallback、拷贝、后处理和带宽 |

## 3. 官网排障路径

MTK 官方把不支持问题分为三类：

1. **Converter 阶段**：源框架算子无法被 NP Converter 识别.先检查新版 Converter 是否支持,再考虑等价改写源图.
2. **NCC 阶段**：TFLite 算子有效,但目标 MDLA 对具体 rank、shape、dtype 或语义不支持.查目标平台支持算子表,必要时改写或裁剪模型.
3. **Runtime 阶段**：板端 Delegate/Runtime 拒绝算子、回退 CPU 或执行失败.核对 Runtime、驱动、固件、系统镜像和模型目标.

官方入口：

- [Handling Unsupported OP and Models](https://genio.mediatek.com/doc/iot-aihub/ai_hub/ai-workflow/troubleshooting.html)
- [G720 TFLite Supported Operations](https://neuropilot.mediatek.com/sphinx/g720/html/l1_supported_operations/l2_supported_operations/supported_operations.html)
- [Example: Pruning the Model](https://genio.mediatek.com/doc/iot-aihub/ai_hub/ai-workflow/troubleshooting/prune_model.html)
- [Neuron Compiler and Runtime](https://genio.mediatek.com/doc/iot-aihub/ai_hub/ai-workflow/neuron-sdk.html)
- [Genio Community](https://genio-community.mediatek.com/)

## 4. 提问或搜索前必须准备的信息

- Genio 型号和 SoC 标识.
- NP 与 MDLA 版本.
- 主机 SDK、Converter、NCC 版本.
- 板端系统、内核、Neuron Runtime 版本.
- 原模型格式、输入输出 shape 和 dtype.
- 完整命令行.
- 从第一条警告到最终错误的完整日志.
- 失败算子名、编号、rank、shape 和 dtype.
- 模型和 DLA SHA-256.
- 问题能否在最小输入或最小子图复现.

不要只提交"模型跑不起来"或最后一行错误.没有平台、版本、完整日志和模型结构信息时,很难判断是工具限制、硬件限制还是运行时兼容问题.

## 5. 本项目已遇到的关键问题

### 5.1 错误目标架构

旧 `mdla3.0` DLA 被 MT8189 Runtime 拒绝.处理方式是改为 `--arch=mdla5.3`.

### 5.2 EDPA 输出桥

MDLA 5.3 普通编译时,输出转换桥被派发到 EDPA 目标,而 MT8189 没有对应硬件,板端出现 unsupported target.处理方式是：

```text
--suppress-output --disallow-bridge
```

随后由 C++ 后处理恢复 MDLA 原生 NCHW INT8 对齐输出.

### 5.3 输出布局误读

三个检测头的有效宽度为 80、40、20,但原生输出可能对应 80、48、32 的 stride.若按连续无 padding 数据解析,会出现置信度、类别和框坐标异常.

## 6. 完整交付证据

| 证据 | 要求 |
| --- | --- |
| 来源清单 | URL、版本、许可证、大小和 SHA-256 |
| 环境清单 | 宿主机、容器、Converter、NCC、板端系统和 Runtime |
| 模型产物 | PT、TorchScript、ONNX、INT8 TFLite、DLA 均非空且有哈希 |
| 板端 Demo | 真实图片、运行日志、检测 JSON 和结果图 |
| 正式精度 | 完整数据集、评测协议、预测结果、COCO 指标和完整性检查 |
| 正式性能 | 逐图耗时、汇总、预热、分位数、峰值内存和 CPU 状态 |
| 运行绑定 | 唯一运行 ID、Git 提交、源码、二进制、DLA、数据集和评测器哈希 |
| 文档 | README、模型卡、精度报告、性能报告、部署与排障说明 |

## 7. 状态边界

| 状态 | 可以说明什么 | 不能说明什么 |
| --- | --- | --- |
| 静态检查通过 | 文件和配置基本合理 | 未证明转换、编译或板端运行 |
| NCC 编译成功 | 已生成目标 DLA | 未证明目标 Runtime 能加载 |
| neuronrt 成功 | DLA 基本兼容并能执行 | 未证明 C++ 业务结果、完整精度和端到端性能 |
| 三张 Demo 正常 | 可视化输出基本合理 | 不能替代完整 COCO 指标 |
| 完整精度完成 | 业务指标已有正式数据 | 未自动证明性能满足要求 |
| 完整交付 | 产物、板端、精度、性能、证据和文档均闭环 | 仍需具体产品确认业务门槛和许可证义务 |
