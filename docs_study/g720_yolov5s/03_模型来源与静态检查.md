# 03 模型来源与静态检查

## 1. 阶段目标

在正式转换和量化之前确认模型来源正确、文件完整、输入输出清楚、图结构可理解,并提前识别算子、动态维度和后处理风险.

## 2. 离线来源准备

模型根目录：

```text
models/perception/object_detection/yolov5s
```

权重由用户在可联网环境手动下载后放入：

```text
models/yolov5s.pt
```

准备脚本：

```bash
bash ./deploy/download_original.sh
```

该脚本名称保留统一交付习惯,但实际不联网下载.它执行以下工作：

1. 检查固定 YOLOv5 源码压缩包.
2. 检查 MTK 官方补丁压缩包.
3. 检查人工放置的 YOLOv5s 权重.
4. 校验 SHA-256.
5. 离线展开源码并应用补丁.

## 3. 模型规格

| 项目 | 规格 |
| --- | --- |
| 输入布局 | NCHW |
| 输入颜色 | RGB |
| 输入范围 | `[0, 1]` |
| 固定输入 | `1×3×640×640` |
| 检测类别 | COCO 80 类 |
| 检测头 | 3 个 |
| 后处理 | sigmoid、anchor 解码、置信度过滤、NMS、坐标回映 |

## 4. 静态检查内容

- 权重能否由锁定版本的 YOLOv5 加载.
- 输入名称、shape、dtype 和动态维度.
- 输出数量、shape、dtype 和布局.
- 导出前后的算子列表.
- 是否存在自定义算子或 MTKEXT 算子.
- 后处理是否被留在模型外.
- 是否存在 Converter 不识别的源框架算子.
- TFLite 算子是否满足 NP8/MDLA 5.3 的硬件约束.
- 输出 tensor 是否存在对齐或量化参数差异.

## 5. 如何查询支持算子

1. 在 [AI Development Resources](https://genio.mediatek.com/doc/iot-aihub/ai_hub/related_resource.html) 确认 Genio 720 对应 NP8、MDLA 5.3.
2. 打开 [G720 TFLite Supported Operations](https://neuropilot.mediatek.com/sphinx/g720/html/l1_supported_operations/l2_supported_operations/supported_operations.html).该页面可能要求 MOL 或对应授权账号登录.
3. 按 TFLite 算子名、版本、输入 dtype、输出 dtype、rank 和 shape 限制逐项核对.
4. 不只判断"表里有没有算子名".同名算子可能只支持部分版本、数据类型或维度.
5. 用 [Visualizing AI Models](https://genio.mediatek.com/doc/iot-aihub/ai_hub/ai-workflow/model_visualization.html) 中的方法检查模型连接、tensor 和 dtype.

## 6. 风险判定

| 现象 | 初步判断 | 下一步 |
| --- | --- | --- |
| Converter 不识别源算子 | 转换器或源图问题 | 查 Converter 文档；考虑等价算子或调整导出 |
| Converter 成功,NCC 报不支持 | 目标 MDLA 硬件约束 | 查 NP8 支持算子表和 NCC 日志 |
| NCC 成功,板端加载失败 | 架构、Runtime 或桥接目标问题 | 核对 DLA 目标、板端 Runtime 和系统库 |
| 板端执行成功但结果异常 | 输入量化、输出布局或后处理问题 | 逐级对比 tensor,不直接调业务阈值掩盖问题 |

## 7. 通过标准

- 来源、版本、哈希和许可证完整.
- 输入输出定义与转换脚本一致.
- 模型没有未解释的动态维度.
- 算子风险已有清单和处理结论.
- 预处理、量化和后处理语义已固定.
