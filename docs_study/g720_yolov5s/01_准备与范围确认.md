# 01 准备与范围确认

## 1. 阶段目标

在开始部署前锁定平台、模型、工具链、数据集、验收指标和交付边界，避免把不同 SoC、不同 YOLO 变体或不同评测协议混在一起。

## 2. 必须确认的范围

| 项目 | YOLOv5s 示例中的确定值 |
| --- | --- |
| 目标板 | Genio 720 EVK |
| SoC 标识 | MT8391/MT8189 |
| NPU | NeuroPilot 8、MDLA 5.3 |
| 模型变体 | YOLOv5s，不是 YOLOv5n、YOLOv5m 或 YOLOv5l |
| 源码版本 | Ultralytics YOLOv5 固定提交 `485da42273839d20ea6bdaf142fd02c1027aba61` |
| 权重版本 | YOLOv5s v7.0 |
| 输入 | batch 1、RGB、NCHW、`640×640` |
| 输出 | 3 个原始检测头 |
| 正式数据集 | COCO val2017，5000 张 |
| 部署精度 | INT8 PTQ |
| 板端集成 | Neuron Runtime C++ API |

## 3. 来源和许可证

- YOLOv5 上游仓库：<https://github.com/ultralytics/yolov5>
- YOLOv5s v7.0 权重：<https://github.com/ultralytics/yolov5/releases/download/v7.0/yolov5s.pt>
- MTK YOLOv5s 官方参考：<https://genio.mediatek.com/doc/iot-aihub/ai_hub/model_zoo/litert_analytical/YOLOv5s.html>
- YOLOv5 许可证：AGPL-3.0。使用、修改、分发或服务化前应单独评估许可证义务。

下载的权重、源码包、官方补丁和 SDK 都要记录：

- 直接下载地址。
- 下载日期。
- 版本或提交号。
- 文件大小。
- SHA-256。
- 许可证或访问权限。

## 4. 验收指标

正式项目应在执行前给出业务门槛。若尚未定义，文档只能分开记录“已实测结果”和“待业务确认门槛”，不能把历史实测值反过来包装成预先设定的通过线。

最低验收维度包括：

- 模型可转换和可编译。
- DLA 可在目标板加载。
- 板端 C++ 输出正确。
- PyTorch、ONNX、INT8 NPU 使用一致评测协议。
- 报告 mAP@0.5:0.95 及量化损失。
- 报告预处理、NPU、后处理和端到端延迟。
- 报告 P50、P90、P95、平均值和峰值内存。

## 5. 通过标准

- 平台、模型、版本和数据集没有歧义。
- 所有外部资源具有可追溯 URL 和哈希。
- 已区分校准数据、冒烟图片和正式精度数据。
- 已说明“链路跑通”“板端验证”“正式精度完成”和“完整交付”的差别。
- 已明确不把其他模型或其他芯片的结果当作 YOLOv5s/G720 结果。
