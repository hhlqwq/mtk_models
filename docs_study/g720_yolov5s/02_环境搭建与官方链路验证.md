# 02 环境搭建与官方链路验证

## 1. 阶段目标

建立可重复使用的主机转换环境、交叉编译环境和板端运行环境,并先确认基础工具和通信链路正常.

## 2. 当前验证基线

| 组件 | 版本或配置 |
| --- | --- |
| 89 宿主机 | Ubuntu 24.04.4 LTS |
| Docker 容器 | Ubuntu 22.04.5 LTS,`hhl_g720_8011` |
| Python | 3.11.11 |
| PyTorch | 2.0.0+cu118 |
| ONNX | 1.13.1 |
| NeuroPilot SDK Basic | 8.0.11 build 20260211 |
| mtk_converter | 8.16.0 |
| mtk_quantization | 8.2.1 |
| ncc-tflite | 8.2.31 |
| 板端 neuronrt | 8.2.16 |
| 目标架构 | MDLA 5.3 |

编译器和板端 Runtime 版本不同,不能只记录"SDK 8".每次交付应同时记录 Converter、NCC、Runtime、系统镜像和板端内核.

## 3. 环境进入方式

在 89 宿主机：

```bash
cd /data/users/hailong.he/github/mtk_models
docker exec -it hhl_g720_8011 bash
```

进入容器后,项目路径保持不变：

```bash
cd /data/users/hailong.he/github/mtk_models
```

## 4. 建议的只读检查

```bash
python3 --version
python3 -c 'import torch, onnx, mtk_converter; print(torch.__version__, onnx.__version__)'
/opt/mtk/NeuroPilotSDK/neuropilot-sdk-basic-8.0.11-build20260211/neuron_sdk/host/bin/ncc-tflite --version
ssh root@192.168.0.92 'uname -a; cat /proc/device-tree/model; neuronrt --version'
```

正式执行时还应保存：

- `/etc/os-release`.
- 容器镜像名称与 digest.
- Python 包版本.
- 编译器版本.
- 板端 Runtime 库版本.
- CPU governor 和频率范围.
- 可用磁盘空间.
- 数据集数量与标注文件.

## 5. 基础链路检查

1. 本地仓库通过 Git 同步到 89.
2. 宿主机和容器看到同一绝对路径.
3. 89 能通过 SSH 访问 92.
4. 89 能向板端传输小文件并校验哈希.
5. 板端可以运行系统自带的 `neuronrt`.
6. 正式数据集和标注已提前放置,板端不在线下载.

## 6. 官方链路的作用

官方示例用于证明工具安装和标准路径基本可用.完成官方示例后仍需要针对 YOLOv5s 做模型静态检查、目标架构编译、板端输出解析和正式精度评测.

## 7. 通过标准

- 版本清单完整且可追溯.
- 宿主机、容器和板端通信正常.
- NCC 可以启动并识别目标架构.
- 板端 `neuronrt` 可以启动.
- 正式资源路径存在,数量检查正确.
- 环境检查没有未解释的关键错误.
