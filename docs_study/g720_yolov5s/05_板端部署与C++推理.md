# 05 板端部署与 C++ 推理

## 1. 阶段目标

在 Genio 720 上完成 DLA 加载和真实图片推理,并用 C++ 实现完整前处理、NPU 调用、输出解析、YOLO 解码和 NMS.

## 2. 板端执行

在编译容器的仓库根目录执行 `bash models/perception/object_detection/yolov5s/deploy/run.sh`,完成构建和上传.登录开发板后进入打印的部署目录:

```bash
# 少量样本检查.
bash run.sh -test

# COCO 全量评价.
bash run.sh
```

两种模式均使用 C++ Neuron Runtime 推理,每次运行生成独立结果目录.前处理、解码和 NMS 由本模型板端代码实现.

## 3. Runtime 集成检查

- 模型加载只在批量运行开始时执行一次.
- 输入和输出 buffer 生命周期覆盖整个推理调用.
- 每次推理前正确更新输入.
- 每次推理后读取对应的新输出,避免复用旧 buffer.
- metadata 中的 shape、dtype、scale 和 zero point 与后处理一致.
- 所有 Runtime 对象和内存在退出路径释放.
- 错误路径也能释放资源并返回非零状态.

## 4. 输出解析重点

本项目 DLA 使用 `--suppress-output`,输出不是普通连续 NHWC 浮点 tensor.后处理必须确认：

- NCHW 顺序.
- INT8 dtype.
- 三个检测头的有效宽度.
- 每行实际 stride.
- scale 和 zero point.
- anchor 和类别数.

如果框位置、置信度或类别明显异常,应先比较输入 tensor 和原始输出 tensor,不应首先修改 NMS 阈值.

## 5. 通过标准

- DLA 在目标板真实加载成功.
- 多张不同图片连续运行稳定.
- 输出 tensor 每次随输入变化.
- 检测框、类别和置信度基本合理.
- C++ 与参考 Python 后处理结果在允许误差内一致.
- 无明显内存泄漏、悬空 buffer 或资源未释放.
- 保存构建命令、产物路径和运行日志.
