# 05 板端部署与 C++ 推理

## 1. 阶段目标

在 Genio 720 上完成 DLA 加载和真实图片推理,并用 C++ 实现完整前处理、NPU 调用、输出解析、YOLO 解码和 NMS.

## 2. 两级验证

### 2.1 neuronrt 冒烟验证

```bash
cd /data/users/hailong.he/github/mtk_models/models/perception/object_detection/yolov5s
bash ./deploy/deploy_board.sh
```

该步骤部署 DLA 和预生成输入,调用板端 `neuronrt`,用于确认：

- DLA 能加载.
- 输入大小和 dtype 可接受.
- NPU 可以完成执行.
- 输出文件数量和大小基本正确.

`neuronrt` 成功不等于业务程序完成,也不证明检测结果、精度和端到端性能合格.

### 2.2 C++ 正式链路

```bash
cd /data/users/hailong.he/github/mtk_models/models/perception/object_detection/yolov5s
bash ./deploy/build_board_cpp.sh
```

C++ 程序负责：

1. 读取 JPEG.
2. letterbox 到 `640×640`.
3. BGR 转 RGB.
4. 根据实际 TFLite/DLA 量化参数生成 INT8 输入.
5. 注册输入输出内存.
6. 调用 Neuron Runtime.
7. 解析三个 MDLA 原生检测头.
8. 处理宽度方向对齐.
9. dequantize、YOLO anchor 解码、置信度过滤和逐类 NMS.
10. 把检测框坐标映射回原图.
11. 输出 COCO predictions 和逐图耗时.

## 3. Runtime 集成检查

- 模型加载只在批量运行开始时执行一次.
- 输入和输出 buffer 生命周期覆盖整个推理调用.
- 每次推理前正确更新输入.
- 每次推理后读取对应的新输出,避免复用旧 buffer.
- metadata 中的 shape、dtype、scale 和 zero point 与后处理一致.
- 所有 Runtime 对象和内存在退出路径释放.
- 错误路径也能释放资源并返回非零状态.

## 4. 输出解析重点

本项目 DLA 使用 `--suppress-output`,输出不是普通连续 NHWC 浮点 tensor.后处理必须确认：

- NCHW 顺序.
- INT8 dtype.
- 三个检测头的有效宽度.
- 每行实际 stride.
- scale 和 zero point.
- anchor 和类别数.

如果框位置、置信度或类别明显异常,应先比较输入 tensor 和原始输出 tensor,不应首先修改 NMS 阈值.

## 5. 通过标准

- DLA 在目标板真实加载成功.
- 多张不同图片连续运行稳定.
- 输出 tensor 每次随输入变化.
- 检测框、类别和置信度基本合理.
- C++ 与参考 Python 后处理结果在允许误差内一致.
- 无明显内存泄漏、悬空 buffer 或资源未释放.
- 保存构建命令、二进制哈希、DLA 哈希和运行日志.
