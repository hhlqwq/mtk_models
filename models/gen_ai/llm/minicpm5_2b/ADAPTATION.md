# MiniCPM5-2B 适配说明

## 转换约定

- 原始输入为固定 revision 的官方权重和分词器,源文件保持不变.
- 转换副本只调整 BPE merges 的序列化格式,保留词表含义.聊天输入使用官方模板,默认关闭思考模式.
- SDK 校准使用单 EOS=130073,运行停止列表保留官方 1/130073.
- 全部投影使用 W4A16.旋转方式、校准数据、优化配置和实际分片均随本次资源记录.
- Prefill 和 Decode 分别导出单张静态图.分片间 A16 尺度不同时显式使用 `Requantize`,只接受同形状 INT16 单尺度接口.
- DLA 目标为 MDLA 5.3,禁止 CPU 桥接;运行的 embedding、I/O 契约与两个 DLA 必须配套.

## 精度检查

先核对原框架与 SDK 浮点转换,再比较量化 TFLite 和板端 NPU,避免混淆结构转换、量化及硬件执行误差.定长 logits 诊断不能替代 MMLU Accuracy 或 WikiText PPL,变长输入还需检查多块 Prefill 和 KV Cache 转移.

历史诊断记录了后段 MLP 的 INT4 权重近似损失和部分内部激活的 A16 截断,不等于当前默认配方和 Python 实现已经完成同版本归因.低越界比例不代表影响可忽略;扩大激活范围也会降低量化分辨率,不能由单层误差改善推断整模精度提高.

当前正式协议为 MMLU 固定 1000 题、57 学科、seed=17,WikiText2 完整 raw test.原始 BF16 存储与本地 FP32 参数计算分别记录;MMLU 保留无聊天模板的 0-shot 单 Token 选项评分,准备时核对原始/转换分词器及完整提示词后的选项 Token 延续.不以官方 MMLU-Pro/Redux 分数验证该千题基线,不以不同题集比较量化掉点.

仅使用 W4A16.误差对照包含原框架浮点、SDK 转换浮点、W4A16 软件执行及同图编译后的 NPU,先做获准的小样本定位,不自动追加千题实验.没有同版本对照和明确验收条件时,不宣称 14.6 个百分点损失合理、量化极限已确定或质量问题已解决.

对比旋转或校准方案时同时固定实际 R1/R2 和输入样本.局部误差改善不直接作为替换依据;当前按用户明确要求启用固定小批量已验证组合,不宣称正式范围评价通过.精度变化按同协议实测记录,没有明确验收阈值时不判定合格或不合格,也不由单次结果推断 W4A16 的精度极限.

## 当前启用方案,2026-10-28

当前启用 `light_hessian16_rotated_w4a16`: 官方权重 revision `f97400052a43d642bbc6e9975e2397e3ae6a6b52`,全部 Attention、MLP 和 LM Head 为 W4A16,外置 embedding 与 KV 接口为 INT16,Hadamard 旋转 seed=0.这是已有候选中固定 16 题板端成绩较好的组合,不是已证明的量化最优解.

校准文本为固定 WikiText2 TRAIN revision 的 64 个随机 512 Token 窗口,seed=17,加 16 条人工短对话,共 80 条输入.SDK 校准生成每层 128 个批次,Hessian 重构从偶数和奇数批次各固定抽取 8 个,共 16 个,覆盖全部 43 个分片,未启用逐层累计误差优化.实际批次名、R1/R2 矩阵、分片和编译产物随正式模型资源保存,不能仅凭打开 `hessian` 开关宣称复现本配方.

已将实际量化分片、静态图、双 DLA、embedding、分词器、配置和旋转资源固化到模型资源的 `build/native_hessian16/`,不再以日期临时目录作为当前模型的唯一来源.默认 `reuse_compiled: true`,转换和编译入口核对配置、官方权重版本、文件大小和内容后复用已验证产物,缺失或不匹配即停止,不自动退回旧配方或重新量化.原始官方资源保持不变.

2026-10-28 按用户要求停止继续优化,只启用上述已测试产物.不将本次资源切换描述为新的精度实测;不追加完整数据集、性能或 RSS 测试.已启动的 opt2/移除实验性编译选项对照被停止,未采用其产物.新增留出题集固定为 seed=29 的另外 16 题,与原 16 题不重叠,覆盖 15 学科,最长 313 Token.停止指令到达时原框架浮点参考已完成,为 12/16;未执行该留出集的候选软件或 NPU 对照,不作为当前配方的验收依据.

后续恢复研究时,先定位量化软件到 NPU 的偏差,再分别比较校准、权重重构和旋转;当前并未证明这些因素的独立收益.如需重新量化,应另行确认实验和重建范围,不要直接删除已固化产物.

## 优化与测试记录,2026-10-26


本轮只使用 seed=17 的固定 16 题,覆盖 13 学科,输入长度 48 至 342 Token;12 题为单块 Prefill,4 题为多块.不运行千题 MMLU、完整 WikiText2、性能或 RSS 评价.官方原始 tokenizer 与实际题目及选项 Token 已在已有新版库中独立核对;旧 SDK 环境不能直接加载原始 tokenizer 的数组形式 BPE merges.

| 同题同 Token 路径 | 答对题数 |
|---|---:|
| 原框架 FP32 参数计算 | 13/16 |
| SDK 浮点 FP32 参数计算 | 13/16 |
| 当时默认 W4A16 静态图软件执行 | 5/16 |
| 同图软件执行,启用 SDK FP16 计算模拟 | 7/16 |
| 当时默认 W4A16 DLA,Python 调用真实 NPU | 5/16 |
| 已有 W4A16 Hessian/旋转组合候选,真实 NPU | 8/16 |

原框架与 SDK 浮点的预测 16/16 一致,四选项分数最大绝对差约 0.000061.浮点适配在本批样本上未见明显退化.软件量化与 NPU 虽然同为 5/16,预测仅 4/16 一致;FP16 模拟后与 NPU 预测为 7/16 一致,不能认为软件与硬件已经对齐.单块题也存在差异,不能只归因于跨块 KV.

已有候选与当前模型使用相同官方 revision,但校准、Hessian 和旋转同时不同.候选修正 6 题、退化 3 题,净增加 3 题,仅说明组合配方在本批样本上有改善,不能归因于单项优化或外推整体 MMLU.当时仅在日期临时目录保留用于 MMLU 的 Prefill 与配套资源,当时没有替换交付包或默认配置;2026-10-28 已按用户要求启用该候选.当前 `results/summary.json` 继续明确保存迁移前历史报告,本轮诊断证据不覆盖该报告.

诊断复用 `tools/llm/evaluate_mmlu.py` 的 `pytorch`、`sdk`、`tflite` 和 `npu` 后端;`sdk` 仅允许最多 16 题,通过 SDK 原生前向驱动读取右侧补齐前的最后有效位置,不发布填充文本的 PPL.`tflite --simulate-fp16` 用于硬件计算精度对照,不改动 DLA.新增 SDK 后端另用本批两题在 CPU 核对入口,预测与已有 SDK 浮点记录一致.过程与逐题四选项分数放日期临时目录,不调用本模型正式 `evaluate.sh`.
