# MiniCPM5-2B 适配说明

## 转换约定

- 原始输入为固定 revision 的官方权重和分词器,源文件保持不变.
- 转换副本只调整 BPE merges 的序列化格式,保留词表含义.聊天输入使用官方模板,默认关闭思考模式.
- SDK 校准使用单 EOS=130073,运行停止列表保留官方 1/130073.
- 全部投影使用 W4A16.旋转方式、校准数据、优化配置和实际分片均随本次资源记录.
- Prefill 和 Decode 分别导出单张静态图.分片间 A16 尺度不同时显式使用 `Requantize`,只接受同形状 INT16 单尺度接口.
- DLA 目标为 MDLA 5.3,禁止 CPU 桥接;运行的 embedding、I/O 契约与两个 DLA 必须配套.

## 精度检查

先核对原框架与 SDK 浮点转换,再比较量化 TFLite 和板端 NPU,避免混淆结构转换、量化及硬件执行误差.定长 logits 诊断不能替代 MMLU Accuracy 或 WikiText PPL,变长输入还需检查多块 Prefill 和 KV Cache 转移.

历史诊断记录了后段 MLP 的 INT4 权重近似损失和部分内部激活的 A16 截断,不等于当前默认配方和 Python 实现已经完成同版本归因.低越界比例不代表影响可忽略;扩大激活范围也会降低量化分辨率,不能由单层误差改善推断整模精度提高.

当前正式协议为 MMLU 固定 1000 题、57 学科、seed=17,WikiText2 完整 raw test.原始 BF16 存储与本地 FP32 参数计算分别记录;MMLU 保留无聊天模板的 0-shot 单 Token 选项评分,准备时核对原始/转换分词器及完整提示词后的选项 Token 延续.不以官方 MMLU-Pro/Redux 分数验证该千题基线,不以不同题集比较量化掉点.

仅使用 W4A16.误差对照包含原框架浮点、SDK 转换浮点、W4A16 软件执行及同图编译后的 NPU,先做获准的小样本定位,不自动追加千题实验.没有同版本对照和明确验收条件时,不宣称 14.6 个百分点损失合理、量化极限已确定或质量问题已解决.

对比旋转或校准方案时同时固定实际 R1/R2 和输入样本.未经整模评价支持的局部修复不替换当前交付模型.精度变化按同协议实测记录,没有明确验收阈值时不判定合格或不合格,也不由单次结果推断 W4A16 的精度极限.

## 证据

2026-10-26 已完成当前默认 W4A16 配方的固定 16 题四阶段诊断,详见 README 的小批量误差定位.原框架与 SDK 浮点均为 13/16,预测全部一致;量化软件与 NPU 均为 5/16,但预测仅 4/16 一致.因此浮点适配在本批样本上基本对齐,量化阶段存在明显退化,软件到硬件仍有额外偏差且算子归因尚未完成.启用软件 FP16 模拟不能消除该差异.

复用已有同 revision 的 W4A16 Hessian/旋转候选,板端为 8/16,相比默认配方净增加 3 题,同时退化 3 题.这不是新增量化配方的单因素实验,未替换默认模型,也未证明量化上限.本轮不运行完整数据集或专项性能评价,不重写历史正式报告.

当前模型的评价指标与短生成证据见 [README](README.md)和唯一的[统一汇总](results/summary.json).不保留历史诊断与逐次实验报告.
