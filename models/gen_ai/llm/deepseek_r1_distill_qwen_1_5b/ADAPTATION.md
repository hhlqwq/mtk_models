# DeepSeek-R1-Distill-Qwen-1.5B 适配说明

## 转换约定

使用固定 revision 的官方权重与 tokenizer,不修改 `original/`.转换副本保留 Q/KV Head=12/2、RoPE=10000、RMSNorm epsilon=1e-6,特殊 Token 以官方 tokenizer 和 generation_config 为准.聊天生成使用官方模板;MMLU 与 WikiText2 评分不套聊天模板.

全部 Attention、MLP 和 lm_head 投影均为 W4A16,外置 embedding、KV、mask、RoPE 和图输出采用实际 INT16 契约.分片连接的 A16 尺度不同时显式 Requantize.生成 Prefill=128、Decode=1 两张静态图,面向 MDLA 5.3 编译并禁止 CPU 桥接.

## 已确认的精度问题

`mask_value=-100` 会使 SDK 浮点模型偏离官方实现.对相同的 4 个 WikiText2 文本块,每块 128 Token、独立重置上下文,共评分 508 个下一 Token,只改变浮点输入的 mask:

| 浮点实现 | mask | PPL | 与官方 logits 的 Top-1 一致率 |
| --- | ---: | ---: | ---: |
| 官方 Transformers FP32 | 框架默认因果掩码 | 93.38109 | 参考 |
| SDK FP32 | -100 | 112.87955 | 77.76% |
| SDK FP32 | -1000 | 92.11169 | 94.88% |
| SDK FP32 | -10000 | 93.38106 | 100.00% |

`-10000` 下 logits 最大绝对误差为 0.000134,平均绝对误差约 0.000004.将空 KV Cache 从 1024 缩短为 1,保留 `-100`,误差不消失.本组对照说明问题来自掩码强度,并非仅由静态图的空缓存长度引起.`-1000` 的 PPL 虽然略低,但 logits 仍偏离参考,不能据此选择它.

因果 mask 在 Softmax 前加到注意力分数上,有限负值必须足以压低被屏蔽位置.本模型不能沿用 `-100` 的假设.这是量化之前即可复现的问题,不能将这部分损失归因于 INT4 或 NPU.

修复使用 `native.mask_value: -10000`.必须重新生成校准数据、量化 TFLite、双静态图、DLA 和 I/O 契约,整体替换部署包.旧图的 mask 量化范围不能表示新值时,仅修改运行配置或裁剪到 INT16 下限不会生效.

重建数据的 mask 实测范围为 `[-10000,0]`,量化分片的 mask scale 为 `0.30517578125`,INT16 的 `-32768` 对应 `-10000`,没有把新负值裁剪回旧范围.

## 量化与硬件误差的判断

修复前的同一 16 道 MMLU 题中,官方 FP32 为 12/16,量化 TFLite 为 6/16,NPU 为 4/16.TFLite 与 NPU 有 14/16 道选择一致,说明较大的退化已在硬件执行前出现,同时硬件数值差异也会改变边界接近的选择.这些是定位用小样本,不代表全量成绩,也不足以确定剩余量化误差来自哪个权重或激活.

修复 mask 后已重新校准、量化、编译双 DLA 并部署,Python 直接调用 SDK 完成双语各 32 Token 的生成检查.相同小样本回归:

| 指标 | 官方 FP32 | W4A16 TFLite | W4A16 NPU |
| --- | ---: | ---: | ---: |
| MMLU,16 题 | 12/16 (75.00%) | 5/16 (31.25%) | 5/16 (31.25%) |
| WikiText2 PPL,4 块、508 次评分 | 93.38109 | 131.80235 | 135.65187 |

NPU PPL 从 247.771996 降到 135.651866,但仍高于官方参考,不能宣布质量恢复.两个量化后端虽然总分相同,仅 8/16 道题选择一致,候选 logits 最大绝对差为 1.259073,必须继续区分量化误差与编译/硬件执行差异.本次未执行全量评价或标准性能/RSS 测量.

在同一第一个 128 Token 文本块上读取 28 层实际量化输出,与已对齐的 SDK FP32 比较:第 0 层平均绝对误差为 0.1236,第 27 层为 4.5046,最后一层余弦相似度为 0.9036.误差自前层出现,后几层继续放大,不能只归咎于 lm_head.此块的输入 embedding 及 28 层间残差输出均未超出各自 A16 范围;这不覆盖 Attention/MLP 内部张量,也未独立分离 INT4 权重近似与内部 A16 舍入/截断的贡献.

检查顺序为官方 FP32 → SDK FP32 → 量化 TFLite → NPU.先固定模型、Token、位置、mask 和 KV 语义,再检查误差首次出现的阶段;不能用一次最终 Accuracy 或单层误差替代整条链路对齐.

## 多轮配方对照

固定官方权重、mask=-10000、上下文 1024 和全 W4A16.筛选使用相同 16 题和 4 个文本块.原始 SDK 分片按相同 128 Token 批长及 1024 后缀缓存执行,与基线静态图的逐题候选分数完全一致,PPL 也完全一致,用于减少候选筛选时重复导出静态图及编译的开销.最终交付仍需编译双 DLA 并完成真实 NPU 复核.

| 校准输入 | 批次 | 权重优化 | 旋转 | TFLite MMLU | 与 FP32 选择一致 | TFLite PPL |
| --- | ---: | --- | --- | ---: | ---: | ---: |
| 16 条自编双语输入 | 32 | 无 | 否 | 5/16 | 5/16 | 131.80235 |
| 16 条自编双语输入 | 32 | hessian | 否 | 4/16 | 4/16 | 155.00970 |
| 训练集均匀 8 段×256 Token + 8 条双语输入 | 32 | 无 | 否 | 5/16 | 4/16 | 128.51207 |
| 训练集均匀 8 段×256 Token + 8 条双语输入 | 32 | hessian,稳定性 0.1 | 否 | 6/16 | 9/16 | 113.62022 |
| 训练集均匀 8 段×256 Token + 8 条双语输入 | 32 | hessian,稳定性 0.1 | Hadamard | 8/16 | 7/16 | 115.19997 |

单独启用 hessian 在现有自编输入条件下使三项筛选指标均退化,该组合不作为默认方案.这不能外推为 hessian 在其他校准分布下无效.

已核对 SDK converter 的校准实现及首层实际落盘数据:16 条记录保存 16 个 Prefill、16 个单 Token Decode 批次.8 段训练文本各 256 Token,生成上限 128,本次对应的 Prefill 校准长度均为 383;其余双语记录对应长度为 83–146.命令的 `-m 128` 是校准时生成上限,不是把输入截到 128.在默认非流式校准下,批次数上限为输入条数的两倍,只把配置从 32 改为 64 不会增加这 16 条输入的有效覆盖;需同时增加不同输入记录.

旋转采用 SDK 的 Hadamard、seed=0.量化前用实际 R1/R2 验证同一 4 块文本的浮点模型:PPL=93.38108,508 个评分位置 Top-1 全部与官方参考一致,logits 最大绝对误差为 0.000243.SDK 在 PTQ 时按本轮保存的 R1/R2 转换原始校准数据的 embedding 和 past values,不把已旋转样本再次旋转.

另固定 seed=73 的 64 题、36 学科,与筛选 16 题无重叠,最长 523 Token,用于独立复核.基线 FP32 为 20/64,NPU 为 23/64,NPU 与 FP32 的选择一致为 25/64.这说明小题组总分波动明显,不能只凭多答对几题判断量化质量;同时检查 PPL、FP32 选择一致性及独立题组.全部仍为小样本,不替代全量评价.候选产物顺序覆盖同一转换目录,比较数据只保留在本文件.

| 板端候选 | NPU 筛选题 | NPU PPL | 独立 64 题 TFLite / NPU | 独立题 NPU 与 FP32 选择一致 |
| --- | ---: | ---: | ---: | ---: |
| 自编输入、无优化、不旋转 | 5/16 | 135.65187 | 未测 / 23/64 | 25/64 |
| 混合训练文本、hessian 稳定性 0.1、Hadamard | 9/16 | 113.12683 | 20/64 / 18/64 | 33/64 |

旋转候选已完成双 DLA 编译及板端双语短生成.NPU 与 TFLite 在筛选题中 11/16、独立题中 50/64 选择一致,候选 logits 最大绝对差分别为 1.08360、1.76979;独立题 TFLite 与 FP32 的选择一致为 31/64.旋转并未消除编译/硬件数值差异,也不能仅凭筛选题得分选为最终方案.

2026-10-26 续查确认,不旋转、混合训练文本、hessian 稳定性 0.1 的已有软件结果还包含同一独立 64 题:19/64 正确,与 FP32 选择一致 41/64,PPL=113.62022.这比旋转方案的 TFLite 选择一致数 31/64 更高,但答对数并未提高,仍不能单凭一个指标确定最终配方.当前转换工作目录和板端配置均为不旋转方案;此前保存的旋转 NPU 结果不能视为当前部署包的实测.

## 不旋转 Hessian 候选的局部误差

2026-10-26 使用同一第一个 128 Token 文本块,对 28 层分别输入 SDK FP32 的真实上一层输出,不累积前层量化误差.每层依次执行原始浮点权重、将七个 Attention/MLP 投影替换为实际 TFLite INT4 权重反量化值的浮点模型,以及完整 W4A16 软件图.仅替换权重的分支保留官方 bias,不进行 A16 量化;mask、RoPE 和空 KV 语义固定不变.原始浮点分支与此前保存的 SDK FP32 层参考逐元素一致.

| 层编号,从 0 开始 | 仅替换 INT4 权重的输出 RMSE | 完整 W4A16 输出 RMSE | W4A16 与仅替换权重分支的 RMSE |
| --- | ---: | ---: | ---: |
| 0 | 0.089227 | 0.098173 | 0.041959 |
| 2 | 0.524411 | 0.537529 | 0.095744 |
| 19 | 0.302378 | 0.309455 | 0.068619 |
| 27 | 1.101581 | 1.112323 | 0.134582 |

28 层中,仅替换 INT4 权重的 RMSE 为完整 W4A16 RMSE 的 90.89%–99.03%.这支持优先检查权重优化,但该比值不是可相加的误差贡献率.完整软件图还包含激活量化、bias 表示及算子执行差异,不能将两分支差异全部归为 A16 截断.这次诊断没有覆盖其他文本、lm_head、多块 Prefill、Decode 或 NPU,也不替代固定小样本和全量精度评价.逐层过程数据保存在当天临时目录的 `deepseek_validation/local_error.json`.

进一步保持相同训练校准数据和全 W4A16,只将 hessian 稳定性从 0.1 改为 0.03,检查首末层的局部误差.两层的 0.1 控制组重新转换后,均与当前量化图输出逐元素一致.末层必须读取当前第 26 层实际量化输出范围;初次独立转换缺少前层范围的结果不纳入对照.

| 层编号 | 稳定性 0.1 的 W4A16 RMSE | 稳定性 0.03 的 W4A16 RMSE |
| --- | ---: | ---: |
| 0 | 0.098173 | 0.101889 |
| 27,匹配前层范围 | 1.112323 | 1.165778 |

0.03 在这两个局部对照中均未改善,本轮不据此重建完整候选或替换默认 0.1.这只说明本次局部输入未见收益,不能推断 0.03 的完整 PPL 或 MMLU.参数筛选数据保存在当天临时目录的 `deepseek_validation/hessian_probe.json` 和 `hessian_matched_probe.json`,后者为匹配前层范围的末层结果.

当前不旋转 0.1 方案的小样本板端配对输入已重新生成,并核对部署包版本、固定题目 ID、Token、参考题目内容及实际图契约.板端当天临时目录 `deepseek_validation/check_current.py` 由用户在当前部署包目录手动执行,依次评价固定 16 题、独立 64 题和 4 个文本块,只将预测和配对结果保存在该临时目录.本轮尚未执行此板端脚本,未发布新 NPU 指标,未改写 `results/summary.json`.

## 可调整参数

| 参数或步骤 | 调整目的与验证要求 |
| --- | --- |
| `mask_value` | 已确认需要 -10000.同时检查 INT16 表示范围及量化后注意力数值,浮点对齐不等于量化质量已恢复. |
| `calibration_train`、校准输入 | 增加真实训练文本和任务相关输入的覆盖,测试集不参与校准.当前 32 个批次覆盖全部 16 条自编输入,每条包含 Prefill 和 Decode,并非只覆盖第一条. |
| `calibration_batches` | 增加有效样本覆盖;重复短文本或只增加批次数不保证改善.核对实际落盘样本和激活范围. |
| `weight_optimization` | SDK 支持 hessian、gradient.混合训练文本和 hessian 稳定性 0.1 的组合已改善固定小样本 PPL;不旋转方案的独立题选择一致数为 41/64,仍需板端配对及全量确认.调整时先检查逐层误差,再做同样小样本回归. |
| `rotate` | 尝试减弱离群值对量化的影响.旋转后权重、embedding、校准数据及两阶段图必须成套重建.已有候选改善筛选题和 PPL,但独立题未同步改善,不据此选为最终方案. |
| 激活范围 | 检查代表性输入是否越过 A16 范围.扩大范围会降低分辨率,不能只凭截断数量减少就判断质量改善.SDK 另提供实验项 `--act_clip_range`,当前模型入口未开放,不能把裁剪当作通用修复. |
| 静态图与板端 | 核对分片 Requantize、多块 Prefill、KV 转移、缓冲区补齐和实际 scale/zero point.保持同一 TFLite/DLA,单独判断编译与运行差异. |

每次只改变一项可解释因素,比较相同输入;不能通过提高权重位宽或缩短题目掩盖问题.全量 MMLU、WikiText2 和正式性能/RSS 由独立评价完成.

当前默认使用正确 mask、混合训练文本和 hessian 稳定性 0.1,不旋转.后续依据单层局部误差优先检查权重优化参数,候选必须经过同一筛选题、独立题组及板端对照.旋转、范围裁剪及编译参数须独立验证,局部层改善不能直接作为修改默认值的依据.

## 资源保留

NAS 只保留官方 `original/`、当前 `build/native/` 转换产物和唯一 `models/` 部署包.板端只保留 `deepseek_r1_distill_qwen_1_5b/`,不保留 `_native` 等历史版本.定位原因与修复依据集中在本文件,过程张量和评分使用日期临时目录;正式评价仍只更新 `results/summary.json`.

## 板端 Python 依赖

Python 3.12.13、NumPy 1.26.4,使用现有 Neuron Runtime.文本解码补充安装 `tokenizers==0.21.4`,从[官方 PyPI](https://pypi.org/project/tokenizers/0.21.4/)下载 [AArch64 ABI3 wheel](https://files.pythonhosted.org/packages/aa/8f/24f39d7b5c726b7b0be95dca04f344df278a3fe3a4deb15a975d194cbb32/tokenizers-0.21.4-cp39-abi3-manylinux_2_17_aarch64.manylinux2014_aarch64.whl),大小 3,012,624 Bytes.该 ABI3 wheel 支持本次板端 Python.

wheel 保存在 NAS 本模型 `runtime/`,安装使用 `python3 -m pip install --user --no-deps --no-cache-dir <wheel文件>`.实际安装位置为当前用户的 `~/.local/lib/python3.12/site-packages/tokenizers/`,已验证导入和版本.推理只从部署包的本地 `tokenizer.json` 解码,不调用模型下载接口.未升级 Python、NumPy、NPU 驱动或 Runtime.
