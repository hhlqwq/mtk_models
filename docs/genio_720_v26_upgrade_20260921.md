# Genio 720 官方 v26.0 eMMC 升级记录（2026-09-21）

## 目标与边界

本次将 Genio 720 EVK 从 Rity 26.0-dev / Linux 6.6.117 升级到 MediaTek 官方
IoT Yocto v26.0 eMMC 镜像,保证 bootloader、kernel、rootfs、firmware、APUSYS、
Neuron Runtime 和 ORT 来自同一次正式发布.

本记录只确认镜像、刷写、系统组件和访问链路.本次没有下载 Model Zoo 模型,没有运行
LLM/VLM,也没有重新执行历史模型的精度或性能评测.

## Windows 解包兼容处理

原始 tar 包包含 27 个 Linux 符号链接.Windows 解压结果没有还原这些链接,导致首次运行
`genio-flash --list` 时缺少无时间戳别名：

```text
rity-demo-image-genio-720-evk.testdata.json
```

根据 tar 成员的原始 link target 在同一 NTFS 卷创建 27 个硬链接,没有复制约 4 GB 的
rootfs,也没有修改目标文件内容.修复后 `genio-flash --list` 成功识别镜像,默认加载：

```text
apusys.dtbo
display-dsi.dtbo
emmc.dtbo
video.dtbo
```

## 升级后板端基线

串口和 SSH 重新采集结果：

```text
设备: MediaTek Genio 720 EVK
系统: Rity Demo Layer 26.0-release (scarthgap)
内核: 6.6.137-mtk+ga246e0c68c39-g429091ed5965
Neuron Runtime: 8.2.16
ONNX Runtime: 1.20.2
llm_cmdline_tool: /usr/sbin/llm_cmdline_tool
```

板端软件与运行前提：

- `neuropilot-bin` 提供 `neuronrt` 和 `llm_cmdline_tool`.
- ORT Provider 为 `NeuronExecutionProvider`、`XnnpackExecutionProvider` 和
  `CPUExecutionProvider`.
- 安装了 APUSYS NP8 driver、firmware、middleware 和 tools.
- `/dev/apusys`、`/dev/apuext`、`/dev/apusys_apummu` 存在.
- `apusys_np8` 和 `apu_top_np8` 内核模块已加载.
- `llm_cmdline_tool` 能启动参数解析；无 YAML 配置时报告缺少配置并退出.

以上不等于 LLM、VLM、DLA 或 ONNX 模型推理成功.每个模型仍需保存真实输入、退出码、
非空输出、Provider/硬件归属、精度和性能证据.

## 网络与 SSH

NetworkManager 的 `Wired connection 1` 已配置为：

```text

IPv4 method: manual
地址: 192.168.0.92/24
```

正式镜像同时启动的 `dhcpcd.service` 曾给 `end0` 追加 DHCP 地址
`192.168.0.254` 并覆盖默认路由.该服务已设置为 `disabled/inactive`,当前只由
NetworkManager 管理 `end0`.

为 `NP`.Windows 主机已经实际执行以下命令并验证 `uid=0(root)`：

```bash

```
