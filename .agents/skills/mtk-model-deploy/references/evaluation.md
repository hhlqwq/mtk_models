# 双入口与唯一报告

## 所有已有及新增模型的职责

编译服务器 compile.sh 完成所有模型转换、量化、编译、固定子集浮点精度并自动上传必要参考.板端 compile.sh 运行相同子集,打印并保存任务精度、损失和小样本 CosSim/RMSE/NRMSE 至 results/summary_test.json,同时生成示例.

编译服务器 evaluate.sh 使用已有模型完成约定全量浮点精度并自动上传必要输入及参考;板端 evaluate.sh 运行同范围全量精度、性能与峰值 RSS,发布 results/summary.json.两份最终报告互相保留,不生成额外报告副本.

主机过程数据在本地日期临时目录;板端必要参考在 build/reference/,当前预测和评分数据在 build/work/,每次运行前覆盖.普通 DLA 位于模型根目录,多文件包在 models/,代码在 board/.正式原始模型仍存 NAS original/,转换中间产物在 build/,不向 NAS 保存评价张量或数据库.

两端公共精度接口由 tools.evaluation.accuracy_result 构造,明确模型、来源、范围、样本数及单位、样本集合标识和指标方向.公共汇总严格读取此接口,不按旧字段猜测报告类型.全量评价不收集输出张量或重复计算小样本数值误差.

## 精度与真实性

终端只显示阶段、必要进度和最终结果,不逐样本重复打印完整命令及成功信息.过程文件只保留覆盖校验、评分或排错必需的预测、张量和解析日志,同一数据尽量汇总保存,不因为位于临时目录就额外复制.兼容现有运行器必需的文件格式,不为减少文件破坏评分与失败定位.

- LLM 的少量生成示例额外显示输入文本及实际聊天模板、Prefill 提示和实时生成文本,结束时显示停止原因与示例位置.此要求不扩展到 MMLU/WikiText2 逐题评分或非 LLM 模型;独立预热和性能测量关闭文本流式打印,仅在测量外提示阶段.
- 编译阶段比较同子集任务精度及少量输出数值误差,不把子集结果当作全量成绩.
- 正式精度核对完整覆盖、预后处理、标签映射、人体框、文本规范化和评分协议,据实说明校准与评价集重叠.
- 参考与 NPU 必须属于同一模型版本和协议,同为 full 不足以证明可比.无匹配参考时记录绝对精度,差值留空并说明原因.
- AP/AR/准确率/WER 的变化用原始值算百分点,PPL 用绝对差或相对变化,不称百分点.
- 缺数据、上下文不足或程序错误时停止,不能截题、丢样本、修改阈值或自动重编译后继续宣称原模型成绩.
- 原生 LLM 按模型约定范围评价: MiniCPM 使用固定 1000 题、57 学科、seed=17 的分层 MMLU 子集和完整 WikiText2 test,DeepSeek 保持完整 MMLU 与 WikiText2 test.正式入口的 full 表示完整执行约定范围,不能将千题子集标为完整 MMLU 基准.核对部署图、配置和输入契约对应同一次转换,接入代码或旧生成样例不能代替新实测.
- 区分官方权重存储 dtype 与本地参考参数/计算精度及设备,本地复现不能标成官方公布分数.MMLU 保留约定的提示词及选项评分,验证完整提示词后的选项 Token 延续,不因模型用于聊天就自动套用 Chat Template.主机与板端共用固定题目清单,变更抽样或协议后不直接比较旧基线.
- 仅做 W4A16.精度退化先区分原框架、SDK 浮点转换、同图 W4A16 软件执行和 NPU 的误差;先获准做小样本定位,不默认增加耗时实验.无同版本对照及明确验收依据时,不把测得的掉点解释为合理损失或量化极限.

## 性能与内存

- 只在评价阶段执行必要预热并记录有效计数、样本单位和计时范围.分别给出纯 NPU 与可用端到端数据,未测分项留空并说明,不使用主机数据替代.
- LLM 区分 Prefill/Decode,记录上下文、输入/生成 Token 数与速度协议.自由生成样例速度不能标为固定 128 Token 基准.
- 推理、评分和性能统计统一使用 Python,RSS 使用实际 Python 推理进程高水位并注明采集范围.不能把系统可用内存下降当成 RSS,也不能把 RSS 当成全部驱动/NPU 内存.从 C++ 或原生 CLI 迁移后重新实测,不沿用旧实现的性能和 RSS 数值.
- 不按指标分别保存对外 JSON/CSV/Markdown,统一在一个 summary.json 内记录精度、性能、RSS、范围和缺失项.

## summary.json 最低内容

模型与量化版本、运行编号、实际平台环境、评价协议和覆盖数量、参考与板端精度及变化、性能统计、进程峰值 RSS 及其范围.单任务可使用清晰的平铺指标,多任务 LLM 可使用 accuracy 子项,不重复存储同一数值.

本次结果核对完成后才发布报告,重复评价更新同一文件.失败、部分完成或未评价须明确标识,不把历史数据标为本次实测.精简旧报告时只保留当前交付版本必要的真实信息,不混合不同版本数据.核实后同步 README、模型总览与注册状态,代码改动本身不更新成已实测.
