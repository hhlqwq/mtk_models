# 双入口与唯一报告

## 所有已有及新增模型的职责

| 入口 | 职责 | 最终产物 |
| --- | --- | --- |
| 容器 deploy/compile.sh | 导出、量化、编译、部署,自动调用板端同名入口检查少量输入 | 模型、必要参数和 README 示例,不输出正式指标 |
| 板端 compile.sh | 检查真实硬件输出并生成展示材料 | examples/output 中少量图像或文本 |
| 容器 deploy/evaluate.sh | 使用已有浮点模型准备同协议参考和评价输入 | 资源目录中的必要输入,不将主机耗时作为板端性能 |
| 板端 evaluate.sh | 使用已有 DLA 评价精度、性能和进程峰值 RSS | 唯一 results/summary.json |

两入口无参数,不保留旧 run.sh 或快速模式兼容入口.正式评价不调用 compile.sh,不重新转换、量化或编译.编译示例不依赖精度评分,不创建或更新正式报告.新模型不能复制旧的多报告结构.

评价文件单独运行时默认全量.板端推理默认小批量并新建过程目录,单独评分或画图读取当天同模型、同范围的最近一次结果;缺少前一步产物时报错,不自动补跑.整条流程共享运行编号,无需逐条传参.已有 run-id 参数仍可指定结果,不另建状态文件.

## 目录

```text
模型/
├── deploy/compile.sh
├── deploy/evaluate.sh
├── examples/input/          少量有来源的展示输入
├── examples/output/         README 使用的结果图或文本
└── results/summary.json      唯一正式评价报告
```

正式模型、tokenizer、张量契约及必要评价输入仍存配置指定的资源位置.普通浮点参考进入板端 models/onnx_reference.json,YAMNet 使用 models/fp32_reference.json,MiniCPM 和 DeepSeek 使用 evaluation/full/.这些是评价输入,不在 results 内复制报告.

预测、日志、缓存和逐任务内部指标放 /tmp/hailongcodex/当天日期/模型_阶段_运行编号/,Windows 使用 D:/tmp/hailongcodex/当天日期/.失败现场保留在那里.不在 results 创建 test/full/latest/运行编号目录,不增加 accuracy_summary.json、summary_test.json 或报告格式副本.清理仅针对当前部署包 results,验证路径边界并拒绝链接越界,不能删除其他任务数据.

## 精度与真实性

终端只显示阶段、必要进度和最终结果,不逐样本重复打印完整命令及成功信息.过程文件只保留覆盖校验、评分或排错必需的预测、张量和解析日志,同一数据尽量汇总保存,不因为位于临时目录就额外复制.兼容现有运行器必需的文件格式,不为减少文件破坏评分与失败定位.

- 编译阶段只检查少量输入、硬件输出和示例,运行成功不等于精度合格.
- 正式精度核对完整覆盖、预后处理、标签映射、人体框、文本规范化和评分协议,据实说明校准与评价集重叠.
- 参考与 NPU 必须属于同一模型版本和协议,同为 full 不足以证明可比.无匹配参考时记录绝对精度,差值留空并说明原因.
- AP/AR/准确率/WER 的变化用原始值算百分点,PPL 用绝对差或相对变化,不称百分点.
- 缺数据、上下文不足或程序错误时停止,不能截题、丢样本、修改阈值或自动重编译后继续宣称原模型成绩.
- 原生 LLM 使用完整 MMLU 与 WikiText2 协议,核对部署图、配置和输入契约对应同一次转换.接入评价代码不代表已经实测,旧生成样例不能代替新模型的正式成绩.

## 性能与内存

- 只在评价阶段执行必要预热并记录有效计数、样本单位和计时范围.分别给出纯 NPU 与可用端到端数据,未测分项留空并说明,不使用主机数据替代.
- LLM 区分 Prefill/Decode,记录上下文、输入/生成 Token 数与速度协议.自由生成样例速度不能标为固定 128 Token 基准.
- RSS 使用实际进程高水位,注明 C++、Python 或原生 CLI 进程范围.不能把系统可用内存下降当成 RSS,也不能把 RSS 当成全部驱动/NPU 内存.
- 不按指标分别保存对外 JSON/CSV/Markdown,统一在一个 summary.json 内记录精度、性能、RSS、范围和缺失项.

## summary.json 最低内容

模型与量化版本、运行编号、实际平台环境、评价协议和覆盖数量、参考与板端精度及变化、性能统计、进程峰值 RSS 及其范围.单任务可使用清晰的平铺指标,多任务 LLM 可使用 accuracy 子项,不重复存储同一数值.

本次结果核对完成后才发布报告,重复评价更新同一文件.失败、部分完成或未评价须明确标识,不把历史数据标为本次实测.精简旧报告时只保留当前交付版本必要的真实信息,不混合不同版本数据.核实后同步 README、模型总览与注册状态,代码改动本身不更新成已实测.
