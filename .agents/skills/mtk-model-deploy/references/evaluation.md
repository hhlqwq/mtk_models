# 评价参考

## 入口与职责

| 入口 | 范围 | 职责 |
| --- | --- | --- |
| 容器 `deploy/run.sh` / 板端 `run.sh` | 固定小批量 | 部署及小批量验证,必要时生成少量效果示例 |
| 容器 `deploy/evaluate.sh` | 全量参考 | 对已有浮点模型推理并准备评价输入,不导出、量化、编译、构建或上传 |
| 板端 `evaluate.sh` | 全量 | 对已有部署包推理、计算精度,保留预测和精度汇总 |

两个入口无参数运行,不保留旧快速参数.内部通过 `MTK_EVAL_SCOPE=subset/full` 同步 Python 与 C++ 范围.全量不调用 `run.sh`,不自动运行部署、Demo、效果渲染、模型大小统计和性能专项.

容器生成的全量参考及输入须单独放入现有板端部署包对应位置,不要为补评价资源重跑部署.普通参考为 `models/onnx_reference.json`,YAMNet 为 `models/fp32_reference.json`;MiniCPM5 为 `evaluation/full/`,包括 MMLU、WikiText2 和 FP32 参考.缺少必要输入时停止并列明文件.

## 小批量规则

范围以当前 `tools/evaluation.py`、`common/cpp/evaluation.h` 及模型配置为准:

| 模型 | 固定范围 |
| --- | --- |
| YOLOv5s / YOLOv8n / FastSAM / RTMPose | COCO 100 张;姿态保留所选图片的人体框 |
| ViT | ImageNet 200 张 |
| MobileFaceNet | LFW 十折,每折正负各 5 对,共 100 对 |
| Depth Anything V2 | DA-2K 100 张及对应点对 |
| YAMNet | ESC-50 每类每折一条,250 条;指标仍按可映射类别和评价折计算 |
| Whisper | LibriSpeech 5 条 |
| MiniCPM5 | 配置中的 MMLU 16 题、WikiText2 4 块及部署功能示例 |
| DeepSeek | 现有固定生成样例,不代表正式基准 |

主机和板端必须选择同一集合.数量不足不得静默缩小.机器报告保留范围和样本指纹,公共说明不堆叠完整哈希.小批量不改变校准/量化配方.

## 全量有效性

- 校验实际覆盖与完整标注一致,不只检查退出码或文件存在.
- 保持预处理、后处理、类别/标签、检测框、文本规范化和评分协议一致,据实说明校准与评价数据重叠.
- 同为 full 仍不保证权重和协议相同.对比前核实模型版本、实际文件和运行契约,不能拿论文数字或其他子集补成同协议基线.
- 缺少匹配参考时可以报告绝对精度,差值留空并说明原因.YAMNet/LLM 的必要协议输入含参考和标签映射,缺失时须先单独准备.
- AP、AR、准确率及 WER 用原始值算百分点变化;PPL 用绝对差或相对变化,不称百分点.
- 不单独跑预热测速和性能 Demo.推理自然产生的诊断耗时可留在原始记录,不作为全量精度的性能验收条件.
- 用独立运行编号隔离全量与小批量,全量 `accuracy_summary.json` 保留精度信息,原始预测和协议不清理.不覆盖仓库已归档指标.

MiniCPM5 全量不依赖 Demo 记录,要求完整 MMLU 14042 题及 WikiText2 test.现有上下文不足时明确阻塞,不能截题、丢题或自动重编译.DeepSeek 当前没有正式全量协议,其入口明确报未实现,不把生成样例标为完整精度.

## 交付判定

记录模型、运行编号、平台/Runtime、模型文件标识、协议、期望与实际数量、指标及预测位置.完整评价失败时不归档成功结论.全量报告经过核实后才能同步模型 README、`results/summary.json` 和模型总览.区分静态审阅、小批量成功、全量实测以及质量是否合格.
