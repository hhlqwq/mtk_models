# MTK 模型部署

所有已有及后续新增模型都交付明确张量契约、两个主要入口、必要展示示例、唯一子集报告及唯一全量报告.优先复用当前仓库工具,不要为单个模型另造环境管理、报告格式或流水线框架.

## 开始工作

1. 读取适用的 `AGENTS.md`,检查 `git status --short`,保留用户改动.只读定位模型 README、配置、模型卡、来源、`deploy/` 和 `results/`;新增模型先查 `registry/target_models.yaml` 与 `registry/models.yaml`.
2. 确定任务为编译部署与展示示例、独立正式评价或诊断.报告改动文件、当前证据和未验证项.按仓库规范在修改代码前确认计划,已有明确批准不重复询问.
3. 部署时读取 [deployment.md](references/deployment.md);评价时读取 [evaluation.md](references/evaluation.md);追溯外部设计时读取 [sources.md](references/sources.md).不要默认加载全部参考.

## 可读性、改动范围与交付检查

- 代码首先要让维护者读懂,命名、条件和执行顺序必须直接表达业务含义.语法合法不是实现合理的依据;不能用隐含兜底、嵌套字段回退或字段存在性猜测主机/板端报告格式.
- 汇总入口只负责顺序调用已有模型入口及必要阶段提示.接入串联流程时先核对原单模型的输入、输出、环境、路径和退出状态,不得顺手修改已正确的预后处理、量化配方、评分协议或推理逻辑.
- 用户新增子集精度或数值对比需求时,明确列出新增步骤和受影响接口,与原流程改动分开说明.主机和板端交给公共汇总程序的精度摘要必须具有明确且统一的字段、指标单位、样本数量和样本单位;不能在公共读取函数中按模型名称和字段是否存在猜测格式.
- 公共链路的修改必须审查全部调用模型的生产端与消费端,逐项核对报告位置、必填字段、数据类型、评价范围、样本覆盖、模型版本和损失方向.发现共性问题先确定全局方案,不得连续给单模型追加条件补丁后交给用户重跑整套流程.
- 语法检查不能证明接口正确或流程可运行.耗时运行前先说明可复用哪些已有结果完成接口验证;未获测试授权时只做允许的审阅和静态检查,明确尚未验证项及所需验证,不得把用户反复运行数小时的整套流程当作基本接口检查手段.
- 修复以最小必要改动为原则,保留已正确的模型实现和真实运行结果.提交前检查差异及全部受影响入口,交付时分别说明代码修改、静态检查、结果接口验证和真实模型运行的完成状态.

## 执行边界

- 普通模型任务遵守本 skill,不得自行修改本文件及参考文件.确需调整时,先说明原因和具体改动并取得用户确认;不得为迁就当前实现而放宽已有要求.
- 本仓库使用现成权重做部署与评价,不新增训练或微调流程.量化校准样本与正式精度评测集分别说明.
- 推理、前后处理、精度评价和性能统计统一使用 Python,通过 Python 调用 MTK SDK 动态库执行 NPU 推理.不新增或维护仓库自己的 C++ 推理程序,不以 Python 启动 C++ 程序代替迁移.现有模型仍含 C++ 实现,仅作为待迁移现状,不能作为新模型的实现规范.

- 主机 deploy/compile.sh 完成导出、量化、编译、部署和固定子集浮点任务精度评估,自动上传必要参考.用户登录板端执行同名入口,运行相同子集的 NPU 精度与损失检查,生成示例,将任务精度及 CosSim/RMSE/NRMSE 保存为 results/summary_test.json.普通模型数值对比最多 5 次输入;LLM 对比示例首个 Prefill,Whisper 对比 Encoder,BEVFusion 对比单帧各 NPU 子图并明确参考执行位置.不通过 SSH 自动启动板端推理,上传成功不宣称板端已验证.
- 仅对 LLM,板端生成示例显示输入文本及实际聊天模板、Prefill 提示,增量解码并立即刷新生成文本,结束时显示停止原因和示例位置.处理未完成的 UTF-8 字符,不以 Token 计数或日志路径代替文本展示.独立性能测量关闭文本流式输出,详细边界见 references/deployment.md.
- `deploy/evaluate.sh` 是独立正式评价入口.容器端仅对已有浮点模型完成约定全量任务精度并自动上传同协议参考和必要输入;板端 evaluate.sh 使用已有 DLA 与程序评价精度、统计性能和进程峰值 RSS.不触发导出、量化、编译、构建或重新部署.
- 每模型 results/ 只保留 summary_test.json 和 summary.json: 前者由板端 compile 发布子集任务精度、损失及数值误差,后者由 evaluate 发布全量精度、损失、性能和 RSS.两阶段互不覆盖,不增加其他 Markdown/CSV/JSON 报告副本.
- 板端普通 DLA 放模型根目录,多文件运行包放 models/,代码放 board/,必要参考及评价输入放 build/reference/,当前过程数据放 build/work/ 并覆盖.原始资源只在运行确有需要时放 original/,不把训练权重和主机编译缓存重复上传.
- 仅维护 compile.sh、evaluate.sh 两个总入口,不提供 upload.sh.回传实现位于总 compile.sh 末尾,板端 compile 完成回传子集报告和示例;板端 evaluate 完成调用其仅回传分支,回传已有两份报告及示例,不得重新触发编译或推理.
- README 必需的少量输入、结果图及文本放 examples/.主机预测、缓存和中间指标放本地日期临时目录,板端放 build/work/ 并覆盖,失败现场不放 results.模型契约、tokenizer 和评价输入属于必要资源,不能为了文件少而删掉运行必需数据.
- 入口直接顺序调用命令,只补充必要阶段提示,工具输出和错误直接显示在终端.不默认增加日志文件、命令包装或额外管理机制;保持整个流程简单干净.
- 主流程独立文件默认无参数运行:主机读取所属模型 config.yaml,板端读取部署包 config.json.入口不重复传配置路径和运行编号.只保留影响行为的参数,不预先补充尚未需要的功能;普通容器步骤使用已配置的 python,板端保留现有 python3.
- Docker 公共环境由创建容器入口和本地配置管理,模型脚本不重复配置 SDK、解释器或 Python 缓存策略.范围和运行编号属于单次执行状态,在入口确定;板端临时目录复用公共工具推导.板端独立运行所需的缓存控制仅放在板端分支,不要误当作 Docker 配置重复设置.
- 临时文件也要精简:只保存运行、评分或排错必需的数据,不默认创建每步状态文件、逐样本日志、多种格式的同义输出或历史副本.逐样本结果优先汇总保存;保留运行器必需的张量、预测和解析日志,新增文件必须有具体用途.
- 两阶段使用相同模型版本、预后处理与 DLA.若契约不能容纳完整评价则停止,不截题、丢样本或在评价中自动重编译.无正式精度协议时报告 partial 和原因,生成样例不得冒充全量精度.
- LLM 的正式 MMLU 固定为 1000 题、57 学科、seed=17,完整执行该范围不等于完整 MMLU 14042 题;WikiText2 保持完整 test,DeepSeek 的题数协议不随之改变.仅做 W4A16,不新增 W8A16 实验.区分权重存储精度和本地参考计算精度,精度损失必须以同版本同题同 Token 对照分析,没有验收依据不判定掉点合理.细节见 references/evaluation.md.
- 未明确要求的测试、耗时任务和大文件下载先确认再执行.修改文件不等于允许执行模型.升级、刷机、重启和停止其他进程按维护授权执行.
- 编译使用 Ubuntu Docker,真实 NPU 验证在目标板执行.先读取本地配置并核对当前环境,不把公开配置模板当作实时设备状态.
- 主机名、地址、凭据和内部绝对路径只保存在本地配置及本地运行记录.正式模型和数据集存 NAS,临时文件使用仓库约定的日期目录.

## 部署与交付

按任务选择必要阶段,复用来源明确且契约匹配的已有产物.

1. **选型与来源:** 新模型先参考高通、地瓜、地平线、英伟达、英特尔等厂商的官方 Model Zoo,核对实际型号、权重版本和精度评测记录,入口见 [sources.md](references/sources.md).优先选择主流成熟、来源与许可明确、评测可复现且适合 MTK 部署的模型,不因版本新或只有演示就优先选择.移植源码和权重仍取官方/原作者来源,厂商移植产物及其成绩作为参考.资源记录具体下载 URL、版本、文件名和用途,不堆叠哈希;未核实来源保持 pending.
2. **环境与可行性:** 读取平台配置和本地覆盖,核对 SDK、Converter、NCC、板端 Python、Runtime 及硬件.算子支持文档受权限限制时说明待核实,不编造支持结论.
3. **导出与量化:** 明确形状、dtype、layout、预处理、输出语义及后处理.先确认浮点参考,再校准量化.记录实际 W/A 位宽及原生 I/O,不能混淆 FP16/INT16 或将全部任务统一成 W8A8.
4. **DLA 与板端推理:** G720 普通模型复用 `tools.deploy.compile_dla` 的 MDLA 5.3 配方,特殊链路按模型实现.Python 调用的 SDK 动态库须匹配板端架构及 Runtime,禁止跨平台覆盖系统库.
5. **编译与子集:** 主机和板端运行相同任务子集,核对覆盖并计算损失,数值误差单独限定少量输入.成功后仅发布 summary_test.json 和必要示例,不启动全量任务或专项测速.
6. **独立评价:** 用户要求后才执行.核对完整覆盖和同协议参考,统计纯 NPU/可用端到端性能、LLM Prefill/Decode 和进程 RSS,明确计时及内存范围.缺参考时差值留空,缺实测时写未完成,不补数字.
7. **报告与文档:** compile 只发布 results/summary_test.json,evaluate 只发布 results/summary.json,两份互相保留,不混用版本或借用旧指标.核实后同步文档和注册状态.新增模型从 templates/model 创建,遵循 tools/check_registry.py 的双入口及两份报告约束.

选型时同时确定评测数据集及划分,核对厂商该型号实际采用的数据集版本、validation/test、样本范围、指标和预后处理协议.当前目标检测使用 COCO val2017 全量 5000 张验证图片;其他任务按对应成熟公开基准选择验证集或测试集,不统称为测试集.不能把数据格式、训练集、校准集或演示图片当作正式精度评测依据.将最终模型、权重、评测协议与参考链接简要写入已有模型说明,不另建选型报告;缺少信息标为未核实,不同协议的成绩不直接比较.

## 模型路由

调用前重新读取当前文件,不要将单模型经验直接外推到新平台.

| 场景 | 仓库参考 | 保留的差异 |
| --- | --- | --- |
| 检测 | `models/perception/object_detection/yolov5s`、`yolov8n` | COCO bbox、letterbox、类别映射、阈值和 NMS |
| 分类 | `models/perception/image_classification/vit_base_patch16_224` | 官方权重版本、归一化、标签顺序和 Top-1/Top-5 |
| 姿态 | `models/interaction/pose_detection/rtmpose_body2d` | WholeBody 133 点、人体框、仿射裁剪、SimCC 和 OKS-NMS |
| 人脸 | `models/interaction/face_recognition/mobilefacenet` | 五点对齐、128 维特征及 LFW 十折阈值协议 |
| 分割与深度 | `models/navigation/segmentation/fastsam`、`models/navigation/single_camera_depth/depth_anything_v2_small` | 类别无关 AR@100 与 DA-2K 点对准确率,不能替换为其他任务指标 |
| 音频 | `models/audio/ambient_sound/yamnet`、`models/audio/stt/whisper_tiny` | 标签投影和评价折;双 DLA、自回归解码与文本规范化 |
| 原生 LLM | `models/gen_ai/llm/minicpm5_2b`、`deepseek_r1_distill_qwen_1_5b` | W4A16 双 DLA、独立 MMLU/PPL 与定长性能评价;保留各模型 tokenizer、停止 Token、GQA 和 KV 契约 |

G720 结果仅证明对应模型、版本和环境.G5100 无实测时保持未验证,先核实目标平台参数,不能复用 G720 编译目标或指标.

## 收尾

中文说明改了什么、实际执行了哪些检查、未运行哪些任务、兼容性影响及剩余问题.区分文件审阅、静态检查、小批量和全量实测.编译成功或版本查询不等于真实推理.完成修改后默认使用中文规范提交说明提交并推送本次任务改动,核对远端与本地提交一致,不混入其他未提交改动.用户明确要求不提交或不推送时按其要求执行.
